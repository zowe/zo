* Run under TSO/ACF with security administrator authority.
* Placeholder names (edit before use):
*   ZWESVUSR = Zowe started task logonid (zowe.setup.security.users.zowe)
*   ZWEINST  = logonid that runs 'zwe components install'
*   ZOENDUID = UID string (or mask) of end users for the optional grants
*----------------------------------------------------------------------

* IMPORTANT: use RECKEY ... ADD(), which adds an entry to an existing rule
* set. Compiling "$KEY(...)" + STORE would REPLACE the whole rule set and
* remove every other user's access (BPX.SERVER is shared with other servers).

* 1. BPX.SERVER (FAC): lets the service logonid create per-user security
*    environments without a password. RACF UPDATE maps to SERVICE(UPDATE).
*    Zowe's own security setup normally grants this already. If no rule
*    exists for BPX.SERVER, involve your security team before creating one:
*    it changes z/OS UNIX server authorization system wide.
ACF
SET RESOURCE(FAC)
RECKEY BPX.SERVER TYPE(FAC) ADD(UID(ZWESVUSR) SERVICE(UPDATE) ALLOW)

* 2. BPX.FILEATTR.PROGCTL: lets the installer run 'extattr +p' on lib/*.so.
*    Only needed if the installer is not a superuser.
RECKEY BPX.FILEATTR.PROGCTL TYPE(FAC) ADD(UID(ZWEINST) SERVICE(READ) ALLOW)

* 3. Certificate and keyring endpoints (optional): per-user R_datalib checks.
RECKEY IRR.DIGTCERT.LIST TYPE(FAC) ADD(UID(ZOENDUID) SERVICE(READ) ALLOW)
RECKEY IRR.DIGTCERT.LISTRING TYPE(FAC) ADD(UID(ZOENDUID) SERVICE(READ) ALLOW)

* 4. Optional APPL gate (NOT yet wired in the extension), via the APL class.
*    Left commented out; enable only when the extension supports it.
*    SET RESOURCE(APL)
*    RECKEY ZOREST TYPE(APL) ADD(UID(ZOENDUID) SERVICE(READ) ALLOW)

* 5. Activate (rebuild in-core resource rules) from the console, then verify.
*    F ACF2,REBUILD(FAC)
SET RESOURCE(FAC)
LIST LIKE(BPX.SERVER)
